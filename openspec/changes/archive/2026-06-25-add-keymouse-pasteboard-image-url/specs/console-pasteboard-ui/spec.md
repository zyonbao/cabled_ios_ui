# console-pasteboard-ui (delta)

## MODIFIED Requirements

### Requirement: 设置剪贴板入口与弹窗

slide6 桌面端与 web 端 SHALL 各提供「设置剪贴板」按钮；点击后弹出输入窗口。仅在设备已连接时该按钮可用。slide6 桌面端输入窗口 SHALL 支持文字或图片两种内容，且**一次只能有一种**：提供文本输入区与「添加图片」入口，以及「确认 / 取消」按钮；当文本输入区已有文字时点击「添加图片」，SHALL 先二次确认「将清空已输入文字」，确认后清空文字并载入图片预览，取消则保持文字。两端在点击「确认」时：若当前为图片，以 `image` 类型写入；否则若文本被识别为单个 URL（去首尾空白后无内部空白且含 scheme+host），以 `url` 类型写入；否则以 `plaintext` 写入。web 端的图片输入为可选实现（端点已支持 `image`），URL 识别两端均 SHALL 实现。

#### Scenario: 确认写入文本剪贴板

- **WHEN** 用户在弹窗输入文本（非 URL）并点击「确认」
- **THEN** 以 `plaintext` 调用剪贴板写入能力（slide6 经 `toolkit_api.set_pasteboard`，web 经 `/api/set_pasteboard`）写入设备剪贴板，并关闭弹窗

#### Scenario: 文本识别为 URL 时按 url 写入

- **WHEN** 用户输入的文本去除首尾空白后为单个 URL（含 scheme，无内部空白/换行）并点击「确认」
- **THEN** 以 `contentType=url` 写入设备剪贴板

#### Scenario: 已有文字时添加图片需二次确认

- **WHEN** 文本输入区已有文字，用户点击「添加图片」
- **THEN** 弹出二次确认提示将清空已输入文字；确认后清空文字并载入所选图片，取消则保持原文字、不载入图片

#### Scenario: 确认写入图片剪贴板

- **WHEN** 弹窗当前为图片内容且用户点击「确认」
- **THEN** 以 `contentType=image` 把图片字节写入设备剪贴板，并关闭弹窗

#### Scenario: 取消不写入

- **WHEN** 用户在设置剪贴板弹窗点击「取消」
- **THEN** 关闭弹窗，不发起任何写入请求

#### Scenario: 设置成功/失败提示

- **WHEN** 确认写入后底层返回成功或失败
- **THEN** UI SHALL 分别给出「已设置」或失败原因的状态提示

### Requirement: 读取剪贴板入口与展示窗口

slide6 桌面端与 web 端 SHALL 各提供「读取剪贴板」按钮；点击后读取设备当前剪贴板。仅在设备已连接时该按钮可用。当「读取剪贴板后自动复制到本机」设置关闭时，按现有行为弹出展示窗口；开启时按「读取后自动复制到本机」要求处理，不弹展示窗口。

#### Scenario: 展示文本剪贴板

- **WHEN** 自动复制设置关闭，用户点击「读取剪贴板」且设备剪贴板为文本内容
- **THEN** 弹出窗口展示该文本内容

#### Scenario: 非文本内容提示

- **WHEN** 读取结果 `isText` 为 false（非文本内容）
- **THEN** 弹窗 SHALL 提示「剪贴板为空或为非文本内容」且不提供复制操作

#### Scenario: 读取成功/失败提示

- **WHEN** 读取剪贴板底层返回成功或失败
- **THEN** UI SHALL 给出「已读取」或失败原因的状态提示

## ADDED Requirements

### Requirement: 读取剪贴板后自动复制到本机设置

Key/Mouse 设置 SHALL 提供「读取设备剪贴板后不弹窗、直接复制到本机」开关，持久化到 keymouse 设置，默认关闭。开启后点击「读取剪贴板」且读到文本内容时，SHALL NOT 弹出展示窗口，而是把文本写入运行控制台的主机剪贴板并提示「已复制到本机」；读到非文本/空或失败时仍按既有提示，不写本机剪贴板。

#### Scenario: 开启后读取文本直接复制到本机

- **WHEN** 开关开启，用户点击「读取剪贴板」且设备剪贴板为文本
- **THEN** 不弹展示窗口，文本写入本机剪贴板并提示「已复制到本机」

#### Scenario: 开启后读到非文本不复制

- **WHEN** 开关开启且读取结果 `isText` 为 false
- **THEN** 不写本机剪贴板，给出「剪贴板为空或为非文本内容」提示

### Requirement: 获取 UI XML 后自动复制到本机设置

Key/Mouse 设置 SHALL 提供「获取 UI XML 后不弹窗、直接复制到本机」开关，持久化到 keymouse 设置，默认关闭。开启后点击「UI XML」且加载成功时，SHALL NOT 弹出 XML 查看窗口，而是把 XML 文本写入主机剪贴板并提示「已复制到本机」；加载失败时仍按既有失败提示。

#### Scenario: 开启后获取 UI XML 直接复制到本机

- **WHEN** 开关开启，用户点击「UI XML」且加载成功
- **THEN** 不弹查看窗口，XML 文本写入本机剪贴板并提示「已复制到本机」

#### Scenario: 关闭时仍弹查看窗口

- **WHEN** 开关关闭，用户点击「UI XML」且加载成功
- **THEN** 按既有行为弹出 UI XML 查看窗口

### Requirement: 拖拽图片到画面区域写入设备剪贴板

slide6 桌面端键鼠操作画面显示区域 SHALL 接受图片文件拖入（`image/*`），并把该图片以 `image` 类型写入设备剪贴板。仅在设备已连接时接受拖入；拖入非图片文件 SHALL 提示「仅支持图片」。拖拽处理 SHALL 与现有点按/滑动/长按手势链路分离，不触发手势动作。（web 端镜像画布的拖入为可选实现。）

#### Scenario: 拖入图片写入设备剪贴板

- **WHEN** 设备已连接，用户把一个图片文件拖入画面显示区域
- **THEN** 读取该图片字节并以 `set_pasteboard(..., content_type="image")` 写入设备剪贴板，给出成功/失败提示

#### Scenario: 拖入非图片文件被拒绝

- **WHEN** 用户把非图片文件拖入画面显示区域
- **THEN** 提示「仅支持图片」，不发起写入

### Requirement: 大图片发送前二次确认

设置弹窗确认写入图片与拖拽图片到画面两条路径，在待发送图片字节数超过 10 MiB 时 SHALL 弹出「图片过大、发送耗时较长」确认框：用户确认后才发送，取消则不发送。

#### Scenario: 超过 10 MiB 弹确认

- **WHEN** 待发送图片字节数超过 10 MiB（经设置弹窗或拖拽路径）
- **THEN** 弹出过大确认框；确认后以 `image` 写入设备剪贴板，取消则不写入

#### Scenario: 未超过阈值直接发送

- **WHEN** 待发送图片字节数不超过 10 MiB
- **THEN** 不弹过大确认框，直接以 `image` 写入设备剪贴板
